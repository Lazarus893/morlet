# 手机与网页分流 + 手机 App 执行（phone）

用户的手机通过 ADB 或 WDA 连接到电脑。你不直接点屏幕：把一句自然语言任务交给「手机执行器」（它自己看屏幕、点屏幕），
执行器分段跑，每段结束把进度、截图交回给你；你把截图发到微信给用户看，他说继续你再续跑。
这套体验和「云手机」是一样的：用户看得见手机在动，随时能喊停、能接管。

## 第一步：分流——先想清楚这事在哪办

拿到需求先做一次判断，不要一上来就开手机：

1. 网页/联网工具能办 → 用 web_search / web_fetch。典型：天气、新闻、常识、营业时间、公开的商品页、公众号文章、地图路线概览、12306 余票、公开评价。
2. 只有 App 里有 → 用本技能。典型信号：
   - 要「我的」数据：我的订单、物流、账单、收藏、购物车、聊天记录、优惠券、会员价。
   - 要定位或登录态才有的结果：附近/距离排序、外卖配送费、个性化推荐、拼团价。
   - 网页版阉割或反爬：小红书笔记正文、闲鱼商品、抖音内容、大众点评完整评价。
3. 两边都能办 → 先网页；网页拿不到或不可信再上手机，并在回复里说一句「网页查不到，上手机看了」。
4. 既不是查也不是办，是聊天 → 都不用。

细则和一张「需求 → 去哪办」的对照表在 references/triage.md，拿不准时读它。
DSH 可以先跑一个独立的意图分流模型，把结果以「[意图分流] route=…」注入到上下文里，带着拆好的 PC 端任务和手机端任务。
有分流结果时优先参考；没有结果时自己按上述规则判断。它给的 mobile_task 可以直接当任务描述用。置信度低（<0.6）或明显不对时按你自己的判断来。
hybrid 的做法：先在 PC 端把公开信息查好（候选、地址、价格），写一份到 shared/notes/<日期>-<主题>.md，再把需要 App 的部分交给手机，最后把两边合成一条回复。

## 第二步：写任务——执行器只认一句清楚的话

写任务前，先读工作区 phone-refs/apps/<App名>.md；首次使用的种子参考也在技能目录 references/apps/<App名>.md（美团.md、小红书.md、支付宝.md……），
里面有入口路径、常见弹窗、敏感动作清单和现成的任务模板。然后照这些规矩写：

- 一次一件事、只进一个 App，第一句就是「打开 X」，X 用 App 全称（高德地图、滴滴出行、大众点评），执行器靠全称加载这个 App 的经验。
- 「附近」「最近的」按手机的位置算，手机可能与用户不在同一地点。需要用户当前位置时先确认他在哪，任务里写具体地名，不写「我的位置」。
- 写清要带回什么：「用 finish 汇报店名、评分、距离」。执行器只会把 finish 里的内容带回来。
- 写明边界：「不要下单」「不要付款」「只看不发」「不要点任何购买按钮」。
- 搜索类写关键词和筛选条件（按距离/按销量/价格区间）；地址写具体地址，不写「我家」——先读 MEMORY.md 把「家」「公司」换成真实地址。
- 多步、要翻页对比的任务，拆成两三个任务分别跑，比一个大任务稳。

## 第三步：跑——命令、暂停、续跑

脚本："$XIAOMAN_PROJECT_ROOT/scripts/pa.sh" phone（直接可执行）。bash 调用时把 timeoutMs 设到 400000。

先确认手机在线：运行时上下文里有一行 `phone: state=…`（每 8 秒刷新）。不是 connected 就先回一句让用户处理（locked 解锁 / unauthorized 点允许 / absent 接线），等他说好了再跑；拿不准就跑 `phone_task.py check`，退出码 0 才开始。

开始一个任务：
```bash
"$XIAOMAN_PROJECT_ROOT/scripts/pa.sh" phone run "任务描述" --checkpoint-every 0
```
- 只读、一次就能查完的任务（查评分、查物流、查路线）用 `--checkpoint-every 0`，一口气跑完。
- 要做选择、步骤多、或者可能碰到钱的任务，不加这个参数，用手机 App 里设的检查点（默认每 8 步暂停一次给用户看）。
- `--max-steps N` 改步数上限（默认取 App 设置，一般 30）；`--no-record` 本次不录屏。

续跑（从上次停的地方接着，上下文不丢）：
```bash
"$XIAOMAN_PROJECT_ROOT/scripts/pa.sh" phone resume last
"$XIAOMAN_PROJECT_ROOT/scripts/pa.sh" phone resume last --note "选第二家"
"$XIAOMAN_PROJECT_ROOT/scripts/pa.sh" phone resume last --approve
```
看状态：`phone_task.py status`。

输出最后几行固定是「结果 / 手机端汇报 / 下一步命令 / 最后截图 / 日志」。按退出码处理：

| 退出码 | 含义 | 你该做什么 |
|---|---|---|
| 0 | 完成 | 把结论和最后截图回给用户|
| 4 | 到检查点暂停 | 把截图发给用户，一句话说到哪了，问他「继续吗」；他说继续就 resume |
| 5 | 需要用户接管（登录、验证码、人脸、滑块，或他在手机上按了「我来接管」） | 把截图发给他，说清手机上要他做什么；他说弄好了再 resume |
| 6 | 遇到敏感操作等批准 | 把截图和「要做的操作」发给他；他明确说「批准/可以」才 resume --approve，否则 resume --note 换路 |
| 3 | 没做完（超步数、超时、出错） | 看输出里的原因；最多再试一次并把任务写得更具体；再不行把截图发给他说卡在哪 |
| 2 | 手机没连/锁屏/环境问题 | 按输出的提示原话告诉他怎么弄，不要自己猜 |

退出码 2 和 3 时脚本末尾会自动附一段「设备状态」（小满 / 模型 API / 手机 / 手机助手 / 微信通道 / 分流器各自 online 还是 offline），把这几行原样带给用户，不要只说出错。

微信里怎么说、截图怎么带，见 references/protocol.md。

## 第四步：回用户

- 结论先行（店名、价格、评分、物流状态），再一句在哪看到的。
- 要带截图，就在回复里放一个 Markdown 链接，路径用输出里「最后截图」那一行，相对工作目录：
  [截图](phone-logs/20261008-1712-ab12/screenshots/013_final.png)
  微信那边会把它当图片发出去。只发工作目录里的文件。
- 检查点和接管时的话术照 references/protocol.md，别长篇大论。

## 共享空间——两边的东西互通

工作区 shared/ 是 PC 端和手机端的交接处：
- 要让手机上的 App 用到的文件（发给朋友的图、要传的文件、要在小红书发的素材）：先放进 shared/to-phone/，再跑
  `phone_task.py push shared/to-phone/xxx.png`，文件会出现在手机的「下载/小满」里，相册和 App 的文件选择器都能选到。
- 手机那边产生的东西（执行器在 App 里保存的图、下载的文件）：让执行器「保存到下载/小满」，每段任务结束会自动拉回 shared/from-phone/；也可以手动 `phone_task.py pull`。
- 混合任务的中间结果写 shared/notes/。
- 云空间：`bin/shared_sync.sh` 负责把 shared/ 同步到云端，云端还没配好，脚本会说明怎么配；配好前不用管它。

## 录屏与复盘——让这套技能自己变好

默认每次任务都录屏（手机 App 里可以关），录像和逐步日志在 phone-logs/<task-id>/ 下。
录屏未授权时，让用户在不投屏的情况下打开「小满手机助手」授权录屏；录屏与投屏互斥。没有录像也能用截图复盘。
用户说「复盘一下刚才」「总结一下」，或者一个任务失败/绕了很多步，就跑：
```bash
"$XIAOMAN_PROJECT_ROOT/scripts/pa.sh" review last
```
它会生成 phone-logs/<task-id>/review.md：时间线、浪费的步数（重复点击、连续 Wait、Back 回退）、
每一步对应的录像抽帧。你读完以后做两件事：
1. 把「下次怎么写任务更顺」「这个 App 的坑」追加到工作区里的 phone-refs/apps/<App名>.md（运行时的可写副本，后续优先读它）的「待实测校准」或对应小节，写日期，一条一行。
2. 把执行器层面的 UI 经验（弹窗怎么关、按钮在哪、何时该 Wait）追加到工作区里的 phone-refs/experiences/<App名>.md，保持短。
这两个目录都在你的工作区里，直接用 edit 改，不需要也不要申请放宽沙箱。改完告诉用户改了什么。只改这两类文件。
只在用户要求复盘、或任务失败/绕路时才做；查完就成功的任务不用复盘。

## 规矩

- 只读优先。付款、下单、转账、发消息、改地址、删东西：执行器会自己停下来等批准，你不要在任务里主动要求它做。
 用户明确让你下单，也先把金额、商品、地址发给他确认，他回「确认」再 resume --approve。
- 登录、验证码、人脸、滑块：停下来交给他，不反复重试。
- 一个任务最多再试一次；两次不行就把截图发给他说明卡在哪。
- 跑之前不用问「要不要用手机」；但一次只跑一个任务，别并行。
- 手机没连、锁屏：按脚本提示告诉他，不要自己猜。
- 不读、不转述跟任务无关的屏幕内容（聊天记录、账单明细只取他要的那一条）。
