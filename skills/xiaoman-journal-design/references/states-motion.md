# 状态与动效

设计选型不返回动画代码。以下是展示服务与组件实现的共同语义，帮助 Agent 选择合适阶段，并避免把视觉反馈当作生活结果。

| 状态 | 文字与保留内容 | 动效／交互 |
| --- | --- | --- |
| 没有事项 | 一句自然交代入口；不填示例成真实账本 | 静态，输入可立即使用 |
| 缺材料 | 显示具体缺口，如候选、数量、时区；已知事实仍可读 | 在原结构就地补齐；不播放失败／完成 |
| 正在设计 | 保留当前布局与内容，简短整理状态 | 不遮罩整页；用户仍可阅读和编辑 |
| 首次生成 | 事项与组件身份明确，主行动先出现 | `reveal`：约 220–320ms，淡入配 4–8px 位移；只在首次进入运行 |
| 保存中 | 保留字段和尺寸，防重复提交 | 就地反馈；不清输入、不提前显示完成勾 |
| 已保存 | 明确「已记下／已选择」及所属事项 | `update`：约 140–220ms，轻底色或短勾变化，回执确认后运行 |
| 保存失败 | 原值、输入与草稿都保留，说明可重试 | 就地错误，不用全页跳转或反复抖动 |
| 新事件／需决定 | 具体事件及下一步；状态不只靠颜色 | `attention`：一次轻强调约 300–450ms；不无限呼吸／闪烁 |
| 布局变化 | 保留用户排序、阅读位置、焦点和编辑草稿 | `layout`：约 220–320ms；编辑中延后重排，提示有更新 |
| 暂停／受阻 | 保留当前进度、已知与缺失；给可选择路径 | 不伪装空白或已完成；不自动重试外部动作 |
| 完成／归档 | 真实完成事实和回看入口保留 | `archive`：约 200–280ms，业务确认后淡出；不突然带走正在编辑的内容 |
| 离线／恢复中 | 显示最后已确认内容与状态时间，保留未提交草稿 | 恢复后先核对事项／版本，再局部更新；不重放未知结果动作 |

默认缓动为克制的 ease-out（例如 `cubic-bezier(.2,.8,.2,1)`），变换和透明度优先。不在常用生活操作上加入弹跳、长时间庆祝、滚动视差或逐字打字。每秒倒计时、持续闪动不是“管家关注”的证据。

系统 `prefers-reduced-motion` 或用户减少动效时，关闭位移、重排过渡和强调动画，保留即时文字反馈。设置为关闭动效时，同样能看到状态和结果。读屏的 `aria-live` 只宣告简短真实回执，不反复朗读整块组件。

所有可交互目标至少 44×44px，有可见焦点、持久标签、hover／active／disabled。移动端正文 16px，不靠缩字塞双列；未来日期、不可选候选或缺条件动作要说明原因，禁用不降低整卡可读性。

打开详情／弹层后焦点进入标题或首个可操作字段，关闭返回原触发位置。后台轮询不覆盖草稿；表单绑定打开时的事项 ID 与版本，身份消失或版本冲突时保留输入并重新核对。排序移至首位导致按钮禁用时，焦点移到同组件可操作控件，不能落到页面空白。

资源 [board-reference.html](../assets/board-reference.html) 的操作只改变当前页面的虚构演示状态；不会保存账本、调度提醒、发送消息或完成外部业务。
