# 安装小满

把小满装成用户自己的独立实例，复用当前已登录的本地 Agent。核心体验是「微信交代 → 管家追问或确认 → 写入生活账本 → 自动组合 Web 手账 → 中断后继续」。不索取额外模型 API key；iMessage、Google、手机和文件权限均可稍后连接。

先读 [安装与恢复](references/install.md)，执行本包 `scripts/xiaoman_setup.py`。脚本和 `assets/framework.zip` 是发布包自带的确定性安装材料；路径均相对此 skill 所在目录，不能引用作者机器或已有实例。只安装此完整目录也足够：框架载荷已包含设计技能及其全部资源。日常看板职责由同包的 `$xiaoman-journal-design` 提供，安装器负责配对及显式装载，不能仅凭复制 skill 文件就报告已接通。

用户需要自动整理与桌宠时，按 [安装与恢复](references/install.md) 的 `connect --desktop-pet` 流程完成官方授权、进程配置与真实产出验收。普通用户只选择账号并在官方页面同意授权；X / Google OAuth 应用配置是发布方前提，缺失时明确报告，不能让用户创建 Developer 应用或填写 Client Secret。

用户明确要求复用本机已有 Google、GitHub 或资料目录时，再按 [复用已有数据源](references/existing-sources.md) 登记可选只读来源。

安装后，或用户问「小满能帮我做什么／先试哪个场景」，读 [生活与工作的四个入门场景](references/starter-scenarios.md)。按用户当下需要选一件：生日筹备、晚餐与采购、邮件日程整理、项目会前准备。已安装时直接进入体验，不重新安装；用户已有明确任务时不让他重新选套餐。示例只提供交代方式和完成标准，不预填真实账本，也不要求一次连接全部数据源。场景由管家推进，设计职责只接收正式材料并选组件。

日常办理按 [管家办理与续做](references/runtime-workflows.md) 取相关来源、保存结构化材料并保留继续点。框架在每轮 `xiaoman_journal list` 回执显式装载此资源，恢复原会话也会读到当前规则；仅复制安装指南不算运行时装载成功。

安装时：

- 先检查当前 Agent 的实际可执行文件，绑定用户选定的 `codex` 或 `workbuddy` 后通过真实执行确认登录可用性。不另建账号或替换其全局模型配置。
- 用用户指定的新目录；未指定时选一个独立目录并说明位置。既有目录先读 `status`，不要覆盖用户的账本、凭据、其他 Agent 或服务。
- 用脚本的持久检查点继续失败或中断的安装；默认安装独立用户 LaunchAgent，关闭终端后继续运行，旧实例用 `service-install` 升级。只停止、重启本实例；`status` 不恢复人工停止，`stop` 停用常驻、明确 `start` 才恢复。先保留未确定任务结果，再决定是否重试。
- 让用户在实例电脑运行 `./scripts/pa.sh owner` 自己设置主人密码。远程手账先配置可信 HTTPS；不使用自动登录 cookie、不替用户设一个通用密码。恢复和撤销见产品 `docs/owner-access.md`。
- 微信二维码、第三方 OAuth 和操作系统权限由用户本人确认。二维码生成、服务启动与 CLI 登录都不等于真实消息闭环通过。
- 安装结果按 [真实验收](references/acceptance.md) 逐项报告：哪些已实测、哪些待用户扫码。没有微信本人输入证据时，不能把模拟事件叫作真实微信验收。

不要在安装过程中发送测试消息给第三人、录屏、读取私人文件，或把示例事项写入真实账本。用户开始真实体验后，默认留空账本。
