# 小满独立 iMessage 接入

按步骤操作及统一命令见 [新用户接入指南](getting-connected.md)。Web 私聊编号可留空，安装器会按指定联系人查找唯一匹配并复核。

## 身份与运行位置

- 小满：独立 Apple 账户及其已验证邮箱，作为对外 iMessage 地址。
- 主人：自己 iPhone 使用的号码或邮箱，仅作为通道允许的发信人。
- Mac：推荐独立的标准 macOS 用户（建议短名 `xiaoman`），其「信息」与桥接程序在同一用户下运行。也可由用户明确选择在当前 macOS 用户内切换「信息」账户；这会替换该用户原来的 iMessage 登录，旧本地会话仍可能保留，需要重新核对收发身份和会话路由。
- 本地 Codex：继续留在原本使用它的用户下；通过 Hub 接任务，不把 Codex 登录凭据复制给消息用户。

Web 配对必须分别填写小满的 `botAddress` 和个人发信人的 `peer`，二者不同；真实地址只进入本机私有配置和实例 Hub。个人设备中“自己右、小满左”；登录小满账户的桥接 Mac 原生方向相反，在这个 Mac 上打开 Web 可保持用户视角。

[Apple 官方说明](https://support.apple.com/zh-cn/guide/messages/ichte16154fb/mac)支持使用邮箱收发 iMessage；若要用手机号作为收发地址，则需要关联已激活 SIM/eSIM 并在 iPhone 配置，见[号码要求](https://support.apple.com/zh-cn/108758)。Apple 账户的验证手机号与 bot 的 iMessage 收发地址分别核对。

## 安装与授权

1. 选择消息桥运行的 macOS 用户。使用独立用户时，在系统设置「用户与群组」创建标准用户；管理员解锁、设置新用户密码及首次登录由使用者完成。保留个人用户登录会话，通过快速用户切换进入消息用户。明确选择当前用户时跳过新建步骤。
2. 在选定用户内打开「信息」，登录专用 Apple 账户并完成验证码/首次激活。核对接收地址和发起新对话地址均为小满的邮箱；切换当前用户已有的个人账户须先由用户明确授权。
3. 将源码白名单包解压到该用户自己的项目目录，安装 Node >=22.19 与官方 imsg。官方 imsg 发布包按官方 Homebrew formula 的 SHA256 核验，完整保留配套资源 bundle。无需私有 bridge，也无需关闭 SIP。
4. 在这个用户下给实际后台宿主授权完整磁盘访问；首次发送时允许控制「信息」。使用后台进程调用 `imsg rpc` 的 `status`，以 `database.ready=true` 验证读权限。个人用户已有的授权和测试结果不能代替这里的验证。
5. 由主人向 bot 邮箱发一条测试消息，或确认收件人和正文后由 bot 发起一条测试。仅核对这条私聊的 chat ID、参与人、服务和收发结果。
6. 服务端 Hub 上线且本地 Agent 已配对后，在同一 Web 会话填写小满收信地址、自己的实际发信地址，生成 iMessage 连接配置；私密配置下载到所选用户，权限设为 0600。运行 `scripts/install-agent-companion.py --kind imessage --config <下载的配置>`。

安装器会核对 chat 身份后创建当前用户的 LaunchAgent。运行数据只保存在该用户项目的 `.runtime/`。共享安装目录只放源码与公开工具；不放密码、配对 token、SSH 私钥或消息数据库。源码可以跨用户复制，私密运行目录不能复制。

安装前也核对该私聊的 `last_addressed_handle` 与小满收信地址。它属于消息路由证据，不能单独证明当前 Apple 登录；初次接入仍需核对「信息」设置和真实双向收发。缺少 `botAddress` 的开发版配置须重新生成；正式常驻桥接尚未部署的实例无需迁移旧状态。

## 运行状态与故障恢复

- 第一次启动记录生效时间和当前私聊游标，历史正文不转为任务；后续启动恢复原游标。输入按 GUID 去重，上传确认前保留本机队列，确认后清除正文、保留去重凭据。
- 每个连接配置旁保存私有 `.state.sqlite`，同机同一数据库/私聊使用排他锁。不要删除状态来排障，也不要同时启动复制的配置。
- 发送前记录 `sending`。重启时未确认的发送转为“结果未知”，不自动重发。系统回执分别展示“已提交、已发送、已送达、已读、失败”；CLI 返回 `sent` 只表示已提交。
- Hub 分开显示消息桥与 Agent 状态。桥接状态包含两方身份、关联会话、最近收信和权限/账号异常；在线只证明近期检查通过，完整业务仍需任务验收。
- 数据库更换、绑定身份变化、权限缺失或本机队列满时保留进度并报错。核对账号和权限后恢复原连接；不要通过清空去重凭据强行恢复。断网期间输入队列上限为 256 条，满后不继续推进游标。
- Web 断开授权后原 token 失效。重新绑定同一双边身份保留渠道标识，让已收过的 GUID 不会创建第二个任务；需要重新安装新配置。

## 验收顺序

1. 主人在自己的 iPhone 上向 bot 邮箱发信，核对实际发信号码或邮箱与 bot 身份不同、接收事件 `is_from_me=false`。同一 Mac 向自己发信不能代替此项；允许发信人按真实入站地址绑定，不假定一定是手机号。
2. 一次收信、一次回复；区分 CLI 接受发送、对端实际收到和对端已读。imsg 返回 `sent` 不能独立证明送达，须核对对端收到或系统送达回执；失败和未知结果不自动重发。当前适配以 `--chat-identifier <发信人号码或邮箱> --service imessage` 使用活动 iMessage 服务，避免 imsg 0.16 的 `--to` 复用切号前旧会话路由。
3. iMessage 消息出现在 Web 统一会话；Web 续聊沿用同一 Codex session。
4. 两个入口可创建/完成同一待办；Web 发信只回 Web，iMessage 来信只回原私聊。
5. 重启桥接程序验证游标和 GUID 去重，不重复执行、不重发未知结果。

小满用户的 GUI 登录会话需保持存在；可切回个人用户工作，不能把退出小满用户当作后台服务仍在运行。重启后应再次登录小满用户并核对实际上线状态，不为此启用自动登录或关闭文件保险箱。

每个安装实例独立完成上述验收；专用 Apple 账户、用户短名、私聊标识、权限状态和验收记录仅保存在本机私有运行目录，不写入发布模板。
