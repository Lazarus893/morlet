# 已授权数据的个人主动关注

## 持续跟进的节点提醒

[日常巡查](routines.md) 默认仅写回原手账。用户在每项跟进中显式选择已有本人 iMessage 或桌面小满渠道后，宿主才为新变化、连续两次受阻及此前已提醒的受阻恢复生成通知。聊天 Agent 不能设置渠道；不会因此开启微信主动发送，也不改变原个人内容推荐的开关或出口。

巡查通知复用 reach-out 的 `Off / Digest / Gentle / Active`、静默、共享额度、会话避让和原消息 outbox。候选按生产者领取，额度仍共享；Digest 中某项失效时，只从尚未发送的摘要中移除该项，保留其他有效内容、原 delivery ID 和已占额度。无变化、同一事实或连续受阻的同一阶段不会反复发。失败提醒发送前已经恢复时取消旧提醒，恢复只记在手账。

巡查暂停、结束、规则变化、来源撤权或换账号、渠道重绑及过期都会让未发送的旧节点失效。绑定身份与资料授权在领取发送前再次核对；发送中或状态未知的动作无法保证撤回，也不自动重发。提醒提供回到原事项的入口，完整结果、来源和失败原因仍在手账中。`submitted`、已发送、送达和已读不是同一状态。

## DSH 桌宠投递

可将已安装的 `dsh-pet` 作为 `desktop-pet` 通知通道。投递复用插件官方 `POST /dsh-pet-7340/broadcast?pet=<id>`，仅传文字，不触发宠物模型；单向投递无须源码补丁，聊天接入另见下文。当前按实际安装的 0.3.7 接口验证；桌面形态需要 DSH 和它拉起的 Electron helper 在线。

安装时由主人认证的 `/api/hub` 调用 `pair-desktop-pet`，提交 `label`、`petId` 和已有 `conversationId`。生成的独立 token 默认只用于消息桥 `status / poll / ack`，不能配置偏好或变更收件人。主人可通过 `enable-pet-chat` 显式开启同一绑定的聊天与推送反馈，具体接法见 [桌宠聊天](pet-chat.md)。个人内容推荐通过 `/api/personal-notices` 的 configure 选择返回的 channelId，同时只选一个出口；巡查在各自事项中另选渠道。原 iMessage 普通对话继续独立可用。

本机私有配置包含 `endpoint`、`publicOrigin`、`token`、`petId`、`hostExecutable`、`helperExecutable`，权限 0600。两个 executable 是已安装 DSH 应用和桌宠 Electron 的绝对路径；不复制可执行文件或资源。将这份文件的绝对路径填入现有 worker.json 的 `petConfig` 后，重载原 notice worker。已有 DSH 集成继续复用原 worker；全新 skill 安装由 `xiaoman_setup.py connect --desktop-pet` 管理独立的官方 standalone 桌宠、连接桥和同一个 notice worker。standalone 配置额外记录精确 `hostArguments` 并核对 helper 父进程，避免把其他 Node 服务误认为桌宠。

投递每十秒检查一次，独立于较慢的来源分析。按当前用户、确切可执行文件身份寻找 DSH 的 loopback 监听端口，重启后重新发现；歧义、宠物未配置桌面显示、helper 离线或 DSH 拒绝访问时停止领取。不会扫描任意端口、跟随 HTTP 重定向或放宽 DSH 访问规则。

内容选择、来源授权、共享额度、暂停、安静时间及会话避让都走原主动关注链路，领取时再核对。发送前持久化未知状态，响应不明或进程退出后只补回执，不再次调用不具备幂等键的 broadcast。成功响应和 state 中匹配的新 counter 只记 `submitted`，不能记送达或已读。pet 接口没有渲染/点击回执，气泡通常显示十秒，实际显示需单独桌面验收；原文和反馈留在手账。

宠物的自动碎碎念、余额和 DSH 工作状态是它自身的独立气泡来源。用作专门的小满通知出口时，可在宠物用户配置中关闭这三项，保留外观与动作。未安装并启用小满聊天桥时，右键聊天仍属于原 pet；启用后，已有输入框会固定实际推送目标并展示反馈按钮，聊天转交现有小满会话。

回归测试使用隔离 Hub 和模拟 pet，不控制用户桌面。真实验收只展示已获用户授权的内容，单独记录宿主提交与桌面可见证据。

## 自动整理到手账

手账中的「自动整理与兴趣」独立控制内容整理，安装默认关闭，由用户开启。复用同一个 Mac worker、已有连接授权、分析提供方和手账 collection 组件；没有新增采集服务。启用后静默时段、消息通道离线或通知 Off 不阻止阅读与保存，但通知仍执行原来的全部门控。Mac 需要在线。

内容模式读取近7天收件箱（最多100条目录，排除促销）、GitHub 公开通知与星标/关注仓库的发布说明和提交说明、X 已授权关注时间线的前20条。每轮轮换最多4条公开通知、2个近期更新仓库，复用 `github-sources.mjs`；不把 stars 当通知订阅，不把普通 PR 动态当用户待办，不标记通知已读。列表分页、单篇长度和外链未读都有覆盖限制，不承诺全量同步。每次模型分析最多12条材料、保存最多6条；剩余材料仍留待后续。X 普通用户只走官方授权，应用注册与额度属于部署方。

保存的摘要、相关性、可选下一步和短引用会同步到服务端手账，每日按邮件/GitHub/X 归入既有 collection。完整邮件/原文仍只存在本机私有缓存与实例已有的模型分析中。二手内容可以作为有归属、明确未核实的来源材料保存，不因此满足主动推荐的一手证据要求，也不会变成用户待办。提交前重新核对正文、账户、授权 generation 与政策；手账条目和来源回执在同一 SQLite 事务提交。断网重试幂等，删除或关闭的当日整理页不会被重新创建。

用户可设置主题、来源和每日上限（1–40，默认18），探索新话题最多占日上限四分之一。「有用」提升优先级；有未撤回的「少推」时，同话题当天最多保留一条，已有条目不删除；「不感兴趣」暂停对应话题。再次点击已选反馈可撤回，打开原文仅计一次弱信号，未回应不扣分。多个反馈存在分歧时，尚未撤回的暂停或少推优先，不用较早的正向分数抵消明确限制。

后台每分钟观察反馈版本，有额度时提前进入下一轮；每日上限已满时等待下一天，不为了演示清空额度或补造反馈。模型读取具体内容的真实反馈样例，判断相似材料的实质价值；宿主在分析后和保存前执行相同的排序、话题数量、探索额度及暂停规则。每批同一普通话题最多两条，正向话题最多三条；有值得探索的新方向时，正常批次为它保留一处位置，不强行填满。未知话题不能通过自行声明 `exploration:false` 绕过额度，只有获得正向明确反馈后才转为持续关注。

每条新内容保存本次采用的偏好版本、选取理由和关联反馈 ID，页面区分“反馈已收到”与“后续已有内容按该偏好选取”。分析、来源重核或断网重试期间反馈变化时，旧版本材料不发布，重新按当前偏好评读；已保存内容的幂等重放保持原回执。具体反馈不会自动授权发通知，通知仍受独立频率与通道门控，少推/暂停话题不会被模型另选为通知打扰用户。

「希望小满怎么说」保存阅读表达偏好，与话题喜好分开。要求语气轻松或减少信息压力不会被换算成点赞或主题降权。新内容用一句有来源依据的小引子作为入口，完整摘要、原文标题和推荐依据展开再读；表达偏好同样参与版本核对，并在后续真实内容中记录是否应用。原有已保存材料不重新捏造摘要或引子。

主动消息必须独立可读：先点名具体对象和变化，再交代一个有意思的发现。普通阅读不强行布置检查或实验，也不把每条材料牵到用户工作上。宿主复用重新核对的仓库名/标题补充上下文，并附本条 GitHub/X 来源或实际引用的一手文章链接；私人邮件和日程没有公开原文时不拼造链接，带凭据或查询串的链接不进入推送。模型正文仍限180字，含上下文和来源的完整消息限500字；Digest 按完整消息总长度选取，不截断各条末尾的来源。hook 同样须点名对象，不能成为脱离上下文的半截悬念。

开启自动整理时，阅读推送必须对应同一账户、来源和候选 key 的已保存条目。被兴趣、探索或数量规则拒绝的候选不能另走通知出口；保存被跳过或失败时也不推送无反馈对象的阅读消息。日程等非阅读提醒仍走原有规则。

在绑定的 iMessage 私聊，最后一条实际送达且24小时内的单项推送，可回复「这条有用」「少推这类」「这类不感兴趣」；多话题摘要或无法定位的回复需在手账中选具体条目，不猜测指代。

GET/POST `/api/automatic-content` 使用原有主人 Cookie/Origin/CSRF，只有 configure 与 feedback。已配对 worker 通过原 `personal-notice-bridge` 的 publish 提交有限来源记录，不能修改偏好或任意手账事项。下述通知门控、投递去重及未知送达处理继续有效；“读取前检查静默”仅适用于未开启自动整理的通知模式。

这是与微信对话跟进独立的主人通知入口。使用主人选定的已绑定通道（iMessage 或桌面小满），微信不会因为它开启而自动启用主动发送。后台扫描由已配对 Mac 上的小满独立服务运行，不依赖当前聊天、Codex 定时任务或打开 Web 页面。Mac、SSH 隧道、消息桥及实例所选的分析 CLI 仍须在线；腾讯服务器不直接读取 Mac 的目录。检查不会创建对话或 Agent 任务，只有被接收的有效提醒进入既有投递记录。

扫描先检查连接和本人通知开关，再只读获取短时间范围的日历、未读邮件、本人 GitHub 待处理请求及已授权常用目录的近期材料。邮件须读正文，适合的资讯还要沿公开链接核对原文，提炼实质内容、与本人兴趣的关系和具体建议。没有具体帮助就不发。完整邮箱正文和文章仅在 Mac 私有缓存及实例既有分析 CLI 中处理；开启自动整理时仅同步所选摘要与短引用到手账；不上传原始本地文件、凭据和私人路径。邮件、文档及网页中的指令是来源材料，不是权限；不会因此授权、购买、替用户回信或给第三人发消息。

默认每天最多两条、间隔三小时，22:00–09:00 静默；时区为实例明确设置的 IANA 时区。每条最多180字，含来源。来源检查须在十分钟内，内容过期、聊天正在执行、最近五分钟互动、消息桥离线或额度已满都不派送。没有为了达到额度而拼凑的开场或营销推送。

需要验证推荐效果时，主人可明确开启有结束时间的验证期。`configure.trial` 包含 `max_daily`（1–20）、`min_gap_minutes`（5–1440）和 `endsAt`（未来、最多30天的Unix毫秒）。验证期只覆盖频率，不修改静默和来源权限；到期根据宿主时间自动恢复原频率，暂停/恢复也不会把验证频率写成永久默认。传入 `trial:null` 可提前结束。

消息语气遵循实例的人设：简短说清替主人留意到的事实，再给一个温和、具体的建议，来源自然放在末尾。需要核对权限等事情时仍应说清事实，不装作已经处理；推荐可以有参考价值而不紧急，不能制造紧迫感、反复催促或以“主人”套话替代有用内容。

Web「提醒偏好」可暂停/恢复。在已选为个人通知出口或某项巡查渠道的 iMessage 私聊、已开启聊天的桌面小满中，发“暂停提醒”“恢复提醒”“提醒设置”有确定性回复，不调用模型。“暂停提醒”关闭共享主动提醒门控，取消未发送候选；巡查、已启用的自动整理和普通来信继续。恢复沿用暂停前模式，不补发已取消的旧提醒；暂停期间用户另改过策略时，不擅自覆盖新设置，需在设置页明确选择模式。各生产者原有开关、资料授权和渠道保持不变。

投递状态仅显示当前通道的记录，不继承其他通道的送达或已读状态。服务端在桥接领取发送时再次检查开关、静默、期限、资料授权和会话；已进入发送的系统操作不能承诺撤回。

## 协议与持久证据

- 已认证主人 Web 会话 GET/POST `/api/personal-notices`，仍受 Host、Origin、Cookie、CSRF 保护；消息桥凭据不能调用主人接口。
- `configure` 仅指定既有验证绑定的 channelId、启停、timezone 和来源枚举；不能改变收件人。未配置默认关闭。
- `offer` 参数为 key、source、text、observedAt、expiresAt。source 为 `google-calendar / google-mail / github / local-files`。key 绑定同一来源事实版本，成功请求再次执行只能回读原 delivery；更改内容须新来源证据，不能为了绕过静默/额度改 key。
- 未满足条件的 offer 不排队，下一次扫描必须重新获取来源；已接收的通知保存在现有 Hub 数据库，预算、去重与普通消息使用同一持久投递记录。
- 通道、收件人和对应会话只取实际绑定。投递状态区分 pending、submitted、sent、delivered、read、unknown、failed；unknown 不自动重发。桥接恢复仍使用原 outbox，不清游标。

回归使用隔离 SQLite/HTTP，不发送真实信息：涵盖权限、跨对象拒绝、持久去重、未知送达、静默和额度、接收时状态变化、暂停后不重发、普通回复不被主动静默影响。

## 小满后台观察服务

已有授权的实例，在私有 `.runtime/personal-notices/worker.json` 指定现有 `connectionConfig`、`agentConfig` 的绝对路径、IANA `timezone`、`interests`（最多12条），可选 `voicePath`、`gog` 与 `gh` 可执行文件。正文阅读需配置 `reading`，包含显式公开域名 `publisherHosts`、其中可作为一手证据的 `primaryHosts`、链接筛选 `topics`，可设 `maxEmails`（默认8）、`maxArticles`（默认6）和 Codex 后台专用的 `reasoningEffort`。缺少阅读配置时不从邮件标题生成推荐。配置权限0600，不能随源码分发。分析使用实例选择的本地 Codex 或 WorkBuddy 适配器；无工具、无写权限、无会话持久化，单批最多120秒，不改变前台 Agent 角色或默认模型。

`node scripts/personal-notice-worker.mjs --once` 会执行真实授权扫描，并可能提交通知；开发验收必须使用隔离目录和禁止 `offer` 外发的 transport，不能把 `--once` 当作 dry-run。部署由 `python3 scripts/install-personal-notice-worker.py` 安装当前 Mac 用户的 LaunchAgent。服务每分钟读取实际启停、来源授权和投递条件，正常每30分钟至多做一次来源扫描；来源收集开始前失败可按退避重试，模型失败不缩短已开始批次的30分钟间隔；醒来或重启后先检查条件，夜间不读取数据。进程有排他锁，状态与请求在网络提交前原子持久化；结果不明只查原回执，不自动重发。源账户、版本和授权在提交前重新核对，服务器继续执行原有频率、静默、会话避让和投递复检。

扫描范围：未来24小时带明确时间且未拒绝的日历事件、近两天最多100封未读收件箱邮件的目录、本人仍开放的 GitHub 审阅请求、已授权常用目录近24小时的文档元信息。邮件分批只读正文，每封最多核对两篇公开文章；未读过的优先，已跳过且未变化的内容六小时后再考虑，已推送事实保持原去重键。批次、正文和分析输入均有限额，超量内容留待后续，不能声称所有邮件都已读完。金融医疗、认证凭据等敏感材料排除，正文中的私人邮箱和手机号在分析前去除。常用目录不递归、不跟随符号链接，不读应用存储、凭据、财务医疗材料、截图录屏和验收样例。单独的文件选择授权不会被扩大成目录授权。文件名仅作兴趣线索，不能独自触发推送；订阅仓库邮件不等同本人待审请求。

文章通过 Readability 与静态 DOM 提取正文，不执行脚本、不加载图片或登录内容；仅 HTTPS 显式允许域名，拒绝私网地址、认证链接和未知查询参数，并逐跳检查重定向、锁定已验证 DNS 地址。付费预览、截断、解析失败都保留覆盖标记；预览不等于读完全文。每封参与分析的邮件都须返回实质摘要、适用性、可选下一步以及逐字可核对的短证据；资讯类推荐必须有完整读取的一手原文依据，无法核实时保留判断并跳过。提交前重新读取邮件与分析时实际使用的文章集合，变化或撤稿则取消本次推荐；单封重验不会重新分配文章预算，避免多读一篇文章被误判成原证据变更。授权 generation 与账号变化同样阻止旧观察继续提交。

本机私有 `reading-cache/` 保存有界正文缓存；`reading-notes/` 保存逐封判断和来源散列，`worker-state.json` 保存进度与去重，不写入源码包或聊天历史；自动整理仅将选中的摘要与引用写入手账。Web「提醒偏好」仅显示本轮完整读取的邮件数、原文数与未读全提示；常规状态桥不传正文、私人路径或评读全文。模型调用仍使用实例所选 CLI 的已有提供方，不能把“本机执行 CLI”理解为离线推理。

`POST /api/personal-notice-bridge` 使用已配对连接桥凭据，提供 `snapshot / status / receipt / analysis / offer / publish` 操作；`analysis` 只预留共享分析额度；不能配置政策、指定收件人、读取对话或执行任务，解除 Mac 配对后立即失效。状态只含计数、时间与有限错误码，在 Web 提醒偏好中展示；常规空检查只记私有 `scan-log.jsonl`，不会进入聊天历史。


## 诊断与恢复

失败状态保存受限的 `diagnostic`：`stage`（如 snapshot、reading、analysis、review、offer）、稳定 `code`、次数 `attempt`、`retryAt`、`retryable`，以及可选 HTTP 状态、耗时和校验原因枚举。不会保存异常原文、HTTP 响应正文、模型回复、邮件、路径、账号或凭据。文章读取失败单独记录阶段、错误码与候选散列；一篇原文 404 不等于邮箱授权失效，也不能被计作完整阅读。

桥接网络错误按1、2、4、8、16、30分钟退避，退避状态持久保存，重启不清零。模型与来源失败保留原批次间隔，期间只核对政策并报告后台状态，不重复调用模型；静默和 Off 仍在任何读取前生效。认证失败只低频检查条件，系统不会替用户重新授权。正常扫描完成清除旧异常诊断；来源变更或政策阻止提交保留 blocked，不能报成正常完成。

`INVALID_READING_REVIEW` 附带 count_mismatch、quote_not_found、primary_missing 等有限原因，仍严格拒绝未经证据支持的推荐，不自动补写引用或把失败改成成功。模型被取消与120秒超时分别记录；未知投递始终只查原回执，不因退避而重发。此前只有 scan_failed 的历史记录无法可靠恢复具体原因，应显示“阶段未记录”。

升级顺序：先部署接受 diagnostic 与 sourceGeneration 的服务端，再重载当前用户的 Mac worker；保留 worker-state、去重、共享额度、政策和凭据。sourceGeneration 是窄桥接的可选升级字段，旧 worker 可在该窗口继续连接，新 worker 提交时携带所读授权版本，服务端再次比较后才接收。

后台分析可使用独立的私有 agentConfig，显式指定当前账号可用的模型。CLI 全局默认不等于该账号实际支持；模型配置更改后 worker 保留已存回执、共享额度和来源授权，重新读取来源。失败分析的额度预留按批次时间窗区分，避免同一批材料在一次错误后永久卡在 already_analyzed；正常重启不会清掉退避。模型不可用、登录过期和限流使用不同的有限诊断码，不上传提供方错误原文。

正文引用如果与已读来源不符，worker 最多调用同一 Agent 纠正一次，重新核对授权并计入既有分析额度；第二次仍不符就拒绝入账。不会用近似匹配、改写原文或取消校验来放行。提示规则版本进入 analysisRevision，规则修复后下一次正常启动会重新扫描，原有已投递回执仍保留。
