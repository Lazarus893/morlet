# 第一件生活事：验收范围与证据

本次改动只覆盖三个 P0：自然交代与必要追问、当前首用事项的持久关联、等待与失败后明确的下一步。生日准备只是计划，保存不代表采购、邀请、订座或生日已经举办。

## 必须成立的产品行为

| 环节 | 应有行为 | 验证方式 |
| --- | --- | --- |
| 自然交代 | 用户可以从“帮我准备周日的生日”开始，不需要知道工具名、版本或字段 | 内网真实 Agent 与浏览器实测 |
| 必要追问 | 只询问当前计划所缺的关键事实；未知预算、地点、人数、价格与日期不得伪造 | 真实模型回应、结构化首用状态与计划核对 |
| 确认计划 | 计划先给用户核对；保存动作只依据当前计划版本的确认 | 隔离 HTTP 与 controller 测试 |
| 专注呈现 | 首用页主要围绕当前交代、追问、计划与下一步，不混入其他会话任务 | 桌面和窄屏浏览器、独立截图复核 |
| 持久恢复 | 首用 flow、专用 Web 会话、执行 run、保存回执与对应 item 可回读；刷新或重新进入不重发、不重写 | 临时 SQLite 关闭重开、内网刷新和重新进入 |
| 保存证据 | 只有宿主写入成功回执才显示入账；报告或猜测 item ID 不算保存成功 | 真 Hub 与 journal 工具、HTTP 回归 |
| 组件生成 | 记录已保存与设计运行是两件事；当前版本 ready 才标明设计完成，失败保留记录 | 首用状态派生、真实设计服务与浏览器 |
| 等待 | 排队、运行、审批、结果未知各有对应说明与操作；刷新只能回读 | controller 状态、浏览器实测 |
| 失败恢复 | 明确返回当前草稿或下一步；确认结果未知前禁止自动重跑，重试与旧 flow 关联 | 受控失败、回执丢失与 lease 回归 |
| 入口边界 | 本轮在 Web 办理，不能复用旧 IM 会话或产生外部消息投递 | source、delivery 与身份检查 |

## 隔离验证与真实验证的边界

隔离测试使用临时数据库和替代模型结果，不控制真实手机，也不发送微信或 iMessage。它们验证协议、版本、恢复与权限，不能证明真实模型理解自然交代，也不能证明第三方业务办成。

真实验收必须保留一条可识别的生日准备事项，并单独核对真实 Agent 的追问、用户确认、journal 写入回执、设计当前版本和刷新后的界面。不得仅用历史手账或完成报告替代本轮证据。

## 验证记录

独立 HTTP 回归 `tests/first_task_http.test.mjs` 当前 7 项通过，使用真实 `createWebUI`、Hub 与 journal 工具及临时 SQLite；未运行真实模型或发送外部消息。

- 页面会话、Host、Origin、CSRF 与跨站请求拒绝后零写入；公开静态资源不能授权 API。
- 从自然生日交代进入专用 Web 会话，依次追问、补充、提案、版本确认。确认前手账为空；保存必须照抄已确认的计划，其他内容拒绝。
- 成功回执绑定本轮的确切事项；同工具调用重放只回读成功回执，另一调用不能重复新增。保存状态为计划，准备步骤仍未完成，基础排版不冒充设计 Agent 成功。
- 关闭并重开真实 HTTP 服务后，未发送草稿与已排队的同一 run 都恢复；读取不隐式开始模型或增加 run。
- 执行结果未知时保留补充，禁止新流程或继续发送绕过核对；用户明确确认停止后，旧 lease 的迟到工具请求被拒绝。
- 另一个页面先保存事项导致 journal 版本冲突时，确认计划的第一次写入确实为零写；读取新版本后可用新调用继续保存，仍只关联当前事项，不覆盖另一条记录。未知写入结果不能使用这个确定零写的恢复路径。
- 另一标签页把新 flow 设为当前后，读取旧 flow 或重放旧请求回执仍返回确切的旧 flow，不能把新的事情当作旧提交的结果；回执回读不修改另一标签页的当前指针。

保存异常的独立回归进一步区分事务证据：实际提交后文件权限检查失败，另一个数据库连接仍可读取保存事实，工具保持结果待核对且禁止换调用重复新增；只有尚未进入事务、明确成功回滚或写入前门禁失败才标为确定零写。回滚失败保留原异常并保持未知，真实 SQLite 锁竞争保留 STORAGE_BUSY 和零写证据，释放锁后允许明确的新调用继续。对应首用 backend 回归 21 项通过。

## 隔离浏览器与独立视觉审查

实现者通过 CUA 在隔离实例验证：自然句草稿保存后刷新保留；发送到真实 Hub 后出现必要问题；补充草稿保存后关闭标签页并重新进入，仍是同一 flow、同一追问与未发送草稿；明确继续后得到待确认计划，手账保持零写。该实例的模型结果为替代结果，不算真实模型理解验收。

独立只读审查了桌面待确认计划截图与源码，按四个维度记录：

| 维度 | 当前结论与限制 |
| --- | --- |
| 可访问性 | 持久标签、44px 操作目标、焦点描边和减弱动画契约存在，桌面正文与操作可读。未把截图审查说成 VoiceOver 或完整 WCAG 认证。 |
| 视觉克制 | 沿用安静的管家风格，无营销大图、无多色渐变、无无意义装饰。 |
| 层级 | 单栏先显示当前阶段，再显示计划内容，主要确认操作清晰；消息历史与连接设置折叠。 |
| 状态 | 待确认显示尚未入账，准备步骤仍是待准备，确认只代表记录计划。无结构化地点时曾显示“地点待定”，与备注中“在家晚餐”矛盾；渲染器已删除这类无来源字段，后续手机截图复核未再出现。 |

独立复核了 375px 内容宽度的空态与待确认计划截图。空态首屏包含真实输入标签、自然例句与整行主动作；计划按事实、准备步骤、确认顺序阅读，主动作位于长内容之后，不抢占核对内容。历史和连接设置仍折叠，主次操作与正文可读。页面整体无横向溢出由实施者的 CUA 测量验证；局部进度文字边界、键盘和读屏行为需以对应浏览器证据为准，不由静态图片替代。

## 真实模型与内网流程验收

本轮使用实例已配置的真实 DSH Chief 和手账设计服务，经正式 Web 页面交代“帮我准备周日的生日”，没有在用户消息中写入工具名或参数模板。Chief 追问生日对象、时间地点、人数预算；补充朋友、周日晚八点、两人、四百元、在家晚餐及试用计划后，生成五步准备提案。确认前，原有三条手账保持不变。

实际关闭页面的两个节点分别为 Chief 处理期间和补充回答尚未发送时。重新进入后恢复同一流程、同一执行轮次和回答草稿；没有因为回读而重新派发。计划页刷新后仍需要明确确认，确认后取得实际 journal 写入回执，新增且只新增一条准备事项。真实设计服务随后以该记录当前版本返回 ready，正式页面展示做饭、分段准备和议程组件，并可打开确切的这一条手账。

三个真实执行轮次均已结束。计划生成轮曾携带工具不接受的额外字段，被拒绝后自行纠正；这一点不计为零工具错误。已记录事实和异步设计成功分别有证据，生日仍是未来的准备计划，五项步骤都未完成；菜单、食材、蛋糕细节尚需继续补充。本轮没有采购、邀请、订座、外部消息或手机操作。

登录受阻、结果未知、回执丢失、版本冲突、取消与迟到回执等异常通过隔离协议/数据库/浏览器验证；没有在生产强制断网、撤销账号或中断保存进程。屏幕和窄屏验证不等于 VoiceOver 或完整 WCAG 认证。私有部署、真实流程关联与截图证据保存在实例的验收目录，不放入产品源码包。
