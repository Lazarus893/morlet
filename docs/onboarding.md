# Morlet 首次使用

先交代一件真实的事。Web、微信和 iMessage 是消息入口；Mori 是默认总管，按需分派给其他 Bot；需要保存的产物进入手账。

## 从已有材料开始

打开「聊天 → Mori」交代第一件事。空手账的「找 Mori」也可开始：若本机有近期已读、带来源依据的材料，会把一条材料带入 Mori 私聊的可编辑草稿；没有材料时，先请你选择资料。仅打开入口不会建立空白引导篇或派发任务，发送后才执行。

看过草稿后补充目标、范围和期限，再发送。已有未发送草稿会被保留，外带内容需要明确选择追加。读取失败、材料变化或提交结果不确定时，先按页面状态核对，不重复派发。

有用的结果保存后，从手账书签回看同一件事：「产物」查看情况说明与 Widget，「对话」补充要求。说明保留未确认范围；来源入口定位原交代，结果入口定位实际 Bot 回报。模型回复本身不等于来源已经核实。

## 自己交代一件事

直接在 Mori 私聊说明你要解决的问题，或从手账「新任务」进入。可以先附上单份资料，也可以指定已授权的数据源；缺少的信息应明确留空。普通聊天不自动建一篇手账，产生需要保存的结果时再入账，详见[用真实资料完成第一件事](first-task.md)。

## 按需连接与恢复

Agent、消息入口和权限放在「设置」。已有在线管家可直接开始；无可用执行端时，在当前任务提供连接入口。消息或连接状态读取失败时，错误及重试显示在页面上方，不要求先展开设置。会话失效须刷新后继续，草稿不会自动发送。

在线、权限授予、实际访问、执行回执分别核对。连接微信仍需本人扫码、允许联系并重新发信；iMessage 仍需收发身份、后台权限和桥在线。另行点击「这是我本人」后，该路线才共享主人的聊天上下文：无 `@` 进入全员群，单 `@` 进入指定 Bot 私聊，多 `@` 在群内协作；结果仍原路返回。未验证联系人保持隔离，见[连接说明](getting-connected.md)。

当前优先桌面体验。选择、跟进和结果回报使用同一套控件，键盘及减少动效模式沿用手账设置。窄屏保留响应式布局，书签目录按需展开。

OAuth、扫码、系统授权和审批由本人确认；引导不会自动申请全部权限、外发消息、购买或订座。目录授权不等于全盘访问，手机在线不等于录屏授权。

查看记录使用 `xiaoman_journal` 返回的可信地址。宿主从实例 `PA_WEB_ORIGIN` 生成 `view.url`；无公共地址则给出导航路径。`#journal/<itemId>` 可直接查看和刷新回看，仍经过当前页面和 owner 账本校验。
