# 日常巡查

用户在手账里交代一次周期任务，小满把它保存为一篇持续更新的事项。日程决定何时检查，回报条件决定何时更新产物。关闭聊天或浏览器不会结束任务；Web 服务、执行 Agent 和所需资料桥仍须在线。修改规则继续在同一篇对话中完成，资料范围与提醒渠道也可在篇内核对。

例如：「每个工作日 9:30 看一下我关注的仓库，有值得跟进的新版本再告诉我。」Agent 先读取实例时间、可用来源和现有巡查，确定检查范围，再通过 `xiaoman_routines` 保存日程和条件；只有取得 `saved: true` 回执才能说已经安排。

## 行为

- Timer 支持每天或指定星期的本地时间，使用 IANA 时区。实例时区优先于服务器所在时区；下一次检查在保存回执和篇首显示。
- Trigger 由 Agent 根据本轮实际读取判断。`changed` 只有条件满足且存在未回报事实才发布；`always` 在条件满足时发布本期结果。事实使用来源事件或版本的稳定 key，不能用检查日期绕过去重。
- 每次检查都有独立执行记录。成功且无变化显示「已检查，无新发现」，保留此前产物；未读、读取失败、部分完成或缺少结构化结果均显示受阻，不能算没有变化。
- 一项巡查固定关联一篇手账。产物保留结果和来源链接，对话用于调整、查看执行或处理授权。后台检查不伪装成用户消息。
- 默认只更新手账。用户可在篇内显式选择已绑定本人的 iMessage 或桌面小满渠道，接收节点提醒；聊天 Agent 不能替用户设置或更换这个渠道。微信不在此通知范围内。
- 暂停会取消未开始的检查，并请求停止在途执行；恢复继续原事项。结束或到达可选结束时间后不可恢复，历史与产物保留。修改规则使旧执行结果失效；执行结果不明时不自动重跑，需先核对。

## 每项跟进的资料范围

每项巡查保存独立 `scope`：`publicWeb` 控制匿名公开网页，`sources` 列出可调用的资料操作与可选精确过滤条件。例如 `github_updates` 可限定一个 `repo`，文件操作必须限定已授权的 `rootId`。过滤条件按字段精确匹配；未限定的字段仍服从原资料接口的权限和参数约束。`publicWeb: true` 授权的是公开网络，不是网址白名单。

连接某个服务不等于每项巡查都能读取它。创建时未提供 `scope` 只允许公开网页，`sources` 为空；要读取账号资料，须按用户交代的范围显式列出操作。服务端绑定当前来源账号、授权版本和提供方，客户端不能自行指定这些绑定。每次排队、资料读取、结果接收和提醒发送前都会核对当前授权。

篇内可查看或缩减范围，设置页会列出使用某项连接的跟进。撤回连接权限、切换账号或重新绑定后，原巡查停止使用失效来源，旧结果不能作为新检查发布，尚未发送的提醒也会失效。重新连接不会自动把新账号授权给旧巡查；用户须在篇内核对后点「重新确认资料范围」。该动作仅限主人界面；普通修改原样保存 scope、恢复任务或聊天 Agent 调用均不能替代它。若同时修改了范围，先保存再核对。

执行能力有明确差异：

| 执行 Agent | 后台巡查能力 |
| --- | --- |
| DSH | 支持受限的原生公开网页搜索/读取；`publicWeb: false` 时禁用。账号和文件资料只走已列入 scope 的受控资料桥。 |
| Codex | 仅支持 `publicWeb: false` 的受控资料读取。尚无可核验的原生网页回执，公开网页巡查返回 `ROUTINE_PUBLIC_WEB_UNSUPPORTED`。 |
| WorkBuddy | 当前不支持此后台巡查，返回 `ROUTINE_SCOPE_UNSUPPORTED`。普通对话与独立内容分析不受此限制。 |

执行端须在本次领取任务时声明支持现有范围保护协议；旧端拒绝领取。后台每次使用新执行会话，不继承人工聊天历史，也不替换人工会话；原生文件读取、命令执行和其他越权工具不开放。已有产物与历史仍留在手账供用户回看。

## 节点提醒

新变化、连续两次检查受阻，以及此前已发出受阻提醒后的恢复，可以生成节点提醒。无变化不发，重复事实和同一受阻阶段不反复提醒。恢复前的失败提醒若尚未发送会撤销，恢复只记在手账。每条提醒带回原事项的入口；没有发布地址时明确指向同名手账。

选择渠道不绕过全局提醒策略。`Off / Digest / Gentle / Active`、静默时间、共享额度、会话避让、渠道在线状态与发送前复核沿用现有 reach-out；不同生产者共享额度，但不会混领彼此的候选。暂停提醒不停止巡查和手账更新，恢复提醒不补发已取消的旧节点。暂停或结束巡查、修改规则、撤回来源、渠道重绑和提醒过期都会使未发送的旧节点失效。

投递状态如实区分等待、排队、已提交、已发送、送达、已读、失败与未知；桌面小满的 `submitted` 只证明宿主接收，不证明气泡已显示。已经发送或结果未知的操作不能承诺撤回，也不自动重发。具体链路见 [个人主动关注](personal-notices.md)。

## 从已读材料继续跟进

自动整理已启用时，可以在对应 GitHub 整理篇下显示少量「持续跟进」建议，最多三条。目前仅从已保存、未过期、含完整一手引用的 GitHub 发布或提交材料生成，核对结构化来源 key、仓库地址、账号和授权版本；任意 GitHub 链接、标题或正文中的指令都不足以产生建议。不会为生成建议额外读取私有资料。

建议明确仓库、每日检查时间与时区、回报条件、资料范围及「仅手账」。默认每天 09:00，优先使用已保存的提醒时区，未设置时使用实例时区。只有用户点击接受才创建独立的仓库跟进事项；后续检查和回报都归入新事项，原整理篇保留。接受前再次核对来源，重复点击或失回执重试不会重复创建。忽略后同一账号的该仓库不再反复建议；已有同仓库跟进、已关闭的来源篇、过期资料或失效授权也不会继续展示。

## 调度与恢复

Web 服务启动后每 25 秒检查到期日程。服务需要保持运行，浏览器无需打开。日程与每期执行存于 Hub SQLite；排队与 occurrence 在同一事务里保存，同一期重复 tick 不重复排队。同一巡查不重叠执行。

重启后最多补查激活后最近一期，不逐条补跑离线期间的积压。新建、恢复或改动日程不会补跑生效前的时刻。夏令时重复小时只取第一次，跳过不存在的本地时间；后续仍按本地日历计算，不用固定加 24 小时。

手账和 Hub 使用各自的持久层：先保存确定的会话，再通过会话 ID 幂等关联手账。中断后恢复同一个事项，不凭标题去重。来源权限仍在每次读取时由现有资料桥复核。

## 接口

`GET /api/routines` 和 `POST /api/routines` 使用现有 owner 会话与 CSRF。后台 Agent 调用使用当前 run 的 endpoint、lease 和 call ID。

- `list` / `get`：日程、当前版本、下一次检查、最近执行及历史。
- `create` / `update`：`values` 包含 `title`、`instruction`、`schedule`（`time`、`timezone`、`days`，周一为 1）和 `trigger`（`condition`、`mode`）；支持 `scope`、可选 `endsAt`（未来 Unix 毫秒或 `null`）及已有 `endpointId`。仅主人接口可写 `notification: { channelId }`，`null` 表示仅手账。
- `pause` / `resume` / `end` / `authorize_scope` / `run_now`：使用事项 ID、当前 `version` 与幂等 `requestId`；`authorize_scope` 仅限主人接口。手动检查仍受暂停、结束、授权、执行状态和去重规则约束。
- `result`：仅当前后台巡查可提交 `outcome: checked | blocked`、`matched`、`summary`、`facts` 和 `checks`。成功检查须说明本轮来源与观察时间；这份声明不是额外的数据访问授权。

`GET /api/followup-suggestions` 返回当前有效建议，`POST` 接收 `{ operation: accept | dismiss, id, version, requestId }`；使用相同主人认证与 CSRF。接受回执含 `saved: true`、创建的 routine 及原 `sourceItemId`。非主人资料范围的手账快照不附带巡查或建议。

`checks` 只是待核实范围。宿主在执行完成时匹配本轮真实读取回执，再保存回执的观察时间：公开网页使用实际请求 URL（标准化并去掉片段），搜索使用 `search:原始查询`，受控资料桥使用 `source-request:execution.requestId`。`xiaoman_sources list` 只证明可用权限，不证明已读取资料。无回执或来源不匹配显示「尚未核实本次读取」，不能发布或记成无变化。

原生网页回执由 DSH 的实际工具结果产生，经当前 run 的 lease 与有序事件流入账；模型不能通过 `result` 写入回执。同一来源以最新一次真实读取为准，完整重读可以恢复此前失败或截断。任何未恢复的网页正文失败或截断都会阻止成功，即使模型漏列该来源、仍声称 `completed`。搜索是有界的发现目录：未被列作检查范围的目录截断，在随后取得完整网页正文时不否决正文检查；若声明已经检查整个搜索范围，搜索回执本身必须完整。资料桥继续使用已授权的 `sourceRequest` 回执，库存列表与正文读取保持区分。

后台只允许查询本次授权来源、当前巡查状态及提交检查结果，不能创建其他巡查、改写业务记录或读取其他事项历史。日程授权不包含发信、购买、删除、改权限或任意 shell 执行；节点提醒由宿主按用户已选渠道处理。已有 DSH 公开网页工具仅允许受限参数；匿名 HTTP 后端继续执行公共地址解析、连接固定、同源重定向和结果上限。网页与来源正文均是不可信数据。
