# 事务 Bot 与安静的 IM 回执

2026-10-28 · 用户已要求先计划后实现。

## 产品决定

Bot 是事务负责人：名字、头像、职责、执行方式、自己的 Routine。DSH / Codex 是底层连接，不再占据聊天的角色选择。默认创建使用 DSH；没有 DSH 时明确显示待连接，不能暗中换到另一执行器。

导航调整为「手账 / 聊天 / 设置」，本次用户要求覆盖原双页约定。手账保留产物与对话分离；聊天按 Bot 查看，固定一个全员群与每位 Bot 的唯一私聊。设置增加「连接 / Bot」两个页签。所有聊天输入支持 @Bot，选择多个时顺序协作，过程和结果标记作者。保留已有草稿、附件、恢复与审批。

总管小满、调研、规划、制作是可编辑的初始职责。总管对未点名的公共来信调用受控分派工具，选一个合适的 Bot 或自己完成；有明确 @ 时尊重用户指定。一次任务的协作继承原会话、材料与手账事项，不产生重复用户消息。不允许递归无限分派。

共享上下文按当前事务传递，保留作者和来源。底层原生会话按 conversation + endpoint + Bot + profile version + context epoch 隔离，显式手账续办还按事项隔离。不同 IM 联系人的正文不自动混在一起；「公共」表示当前来信可由不同 Bot 协作，不表示所有联系人公开互看。

## 实施顺序

1. 去掉三秒后固定文字回执。实机核对 imsg 0.16.0：普通 Tapback 无法精确定位消息，GUID 接口需要放宽系统保护。本轮两个渠道均静默，不冒充 reaction；待有受支持的精确接口再接入。保留执行异常、审批与结果。
2. 增加 Bot 台账、版本校验、默认角色、创建/编辑/停用、DSH 默认解析；消息/run/routine 带 botId。新增受控分派工具和共享任务上下文，取消/停用可阻止后续领取。
3. 聊天页与设置 Bot 页签；复用现有 PAChat、OpenUI 控件、认证、上传与任务账本。输入补全 @，Bot 选择替代执行器选择；Routine 展示和创建绑定负责人。
4. 用内置 imagegen 生成四个独立头像，统一柔和拟物材质、抽象小物件和森林绿/石白底色，小尺寸仍清楚。仅公开通用头像进入源码，不包含私人材料。
5. 验证静默收件、@ 单/多 Bot、总管分派、共享上下文与跨联系人隔离、版本变更、停用、独立 Routine、幂等与失败恢复。运行相关测试/构建与全量检查，在 PC 浏览器走完整路径并按 Huashu / Taste 复审。

## 验收边界

- 不发送真实测试 IM，不控制真实手机。实测 CLI help 已证明 reaction 的目标限制，不调用 UI 自动化发送；实际渠道发送单列未验证项。
- Bot 停用不删除历史，不扩大来源授权。Routine 沿用原有范围、撤权检查和安静通知策略。
- 不承诺未接入的渠道 reaction；不将排队、分派、生成建议写成已完成。
- 私人配置只写 .runtime；发行新增文件逐项登记 config/distribution.json。

## 视觉判断

沿用已确认手账方向，不重选页面风格。聊天用窄 Bot 目录和紧凑正文，两层信息即可；头像承担识别，名字承担定位，不堆角色标签、说明卡或通知计数。连接细节收在设置，离线和错误必须可见。Huashu 检查任务/形式、层级、密度、材质一致与交互；Taste 使用 app-screens 规则。


## 追加：异步通讯与英文产品名

用户在第一轮完成后明确要求并行委派调研、工程实现和命名。调研依据为官方 Grok Bot 的 [协作文档](https://docs.x.ai/grok-bot/chat-and-collaboration) 与 [inference hooks](https://docs.x.ai/grok-bot/inference-hooks)：Bot 间异步消息会唤醒接收者，回复与交接不等于直接对外发布。原厂底层队列、数据库、协议和去重实现未公开。

下一层实现继续复用本地 Hub 账本：任务内的定向 request/result、replyTo 关联、接收者唤醒与原负责人续办，正常最终回报只进入一次 IM outbox。参与者和资料范围从当前事务继承；首用确认和后台 Routine 不开放任意互相委派；问答和总管收尾均有预算。避免靠多 Bot 自动互聊扩大本轮授权或造成通知噪音。明确取消立即生效；普通新增消息仍使用现有会话排队，不承诺实时抢占正在运行的模型。

产品英文名为 **Morlet**，沿用手账、安静管事和抽象小伙伴的方向。小满继续作为总管角色；已有工具协议、数据库路径、环境变量和已安装 App 名不作盲目重命名。已更新主界面、登录页、连接指引、README 和产品介绍；旧截图明确标注旧版。基础重名检索不是商标结论。

## 固定房间与上下文过期

Web 通过 `open-room` 幂等取得唯一私聊或全员群。新建 Bot 自动进入全员群；本轮不提供自建群和新建会话。旧会话及其 ID 保留，符合条件且无 IM 绑定的最近同 Bot 对话可以成为固定私聊；旧材料不批量拼接。

上下文以用户发言计算 24 小时闲置期，下一条发言开启新代际。轮询、重复请求与后台任务不续期；在途任务及其协作子任务保持提交时的代际，迟到回复不能回流到新代际。历史和产物保留，显式续办可读取本篇当前材料。普通房间发言不自动归入唯一旧事项，新建手账事项按请求标识幂等创建。

IM 入口按 channel/account/peer 隔离，与 owner 私聊、全员群分开；旧混合路由首次再使用时拆出独立收件房间，旧运行仍按原来源回报。`/new` 与 `/reset` 只更新未来上下文，不取消已在执行或排队的任务；取消使用明确取消命令。
