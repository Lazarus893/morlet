# 主动跟进：观察者与狙击者

2026-10-17 更新：观察者、跟进和个人资料关注共用 Off / Digest / Gentle / Active 门控，默认 Digest；详见 [可信处理与主动关注](chief-sla.md)。

第一版聚焦用户在对话中提过的待办与后续跟进。目标是把有用的信息放到合适的时机，帮助用户准备、记住和收尾。衡量价值看提醒是否促成准备与完成，不看发了多少消息。

## 两个角色的职责

**观察者**读取本次用户消息与该用户的待办摘要，识别具体待办、时间窗口、修改、完成和取消。每个候选保留一段用户原话作为依据，没有依据不入账。推断置信度低、时间不清楚的精确提醒不登记。无指定时间但明确有跟进价值的事项，先安排约 4 小时后的一次候选跟进，仍须通过后续时机判断。

**狙击者**只处理已经进入时间窗口的候选。先执行确定性的发送约束，再选择是否值得出现、用哪一两句话表达；生成后再次检查用户是否发来了新消息、暂停或完成。低价值跟进可以放弃，模型失败时只给明确预约的提醒使用简短事实文案；普通推断跟进保持沉默。未回复不等于没完成，也不触发反复催促。

例如用户说“周五见客户，西装还没熨”：观察者记录需要准备的事；到了合理的准备时间，狙击者可以提醒检查西装和出行安排。它不会声称已经熨好衣服、叫到车，更不会默认代用户下单。

两个角色复用使用者选择的 DSH/Codex/WorkBuddy 核心，不额外要求另一家的模型 key。普通聊天与观察并行，观察者不追加一条“已分析”的消息；明确“提醒我”的请求先取得持久化回执，再由对话核心回复。后者会增加一次模型调用的等待，单次后台调用最多 60 秒。

## 首次使用

不发送无事项的通用开场。首条消息只建立上下文；确有待办或资料候选后，才进入共享门控。空候选、暂停和静默在模型分析前判断，不为检查是否需要说话调用模型。

## 默认打扰预算

| 规则 | 默认值 |
|---|---|
| 每人每天主动消息 | 共享额度最多 2 条 |
| 两次主动发送之间 | 至少 180 分钟 |
| 静默时间 | 22:00–09:00，按配置时区 |
| 最近用户互动 | 至少安静 5 分钟；正在处理对话/审批时暂缓 |
| 每次信息量 | 单条跟进最多 180 字；摘要合并有界候选 |
| 对话观察预算 | 所有主动分析共享每天最多 40 次 |
| 未指定时间的跟进 | 一次候选，约 4 小时后；不因没有回复自动重发 |
| 明确提醒的迟到窗口 | 通常最多 4 小时；有较晚明确截止点的事项到截止点过期 |

这些约束也适用于明确预约的提醒。因此这版是生活跟进助手，不是精确闹钟；静默、额度和离线可能导致延后或过期。近期过期事项会显示在提醒列表，不集中补发旧消息。每天额度按用户时区的日历日期计算，支持 IANA 时区和夏令时。

## 使用与控制

电脑配置：

```bash
./scripts/pa.sh init --proactive on --timezone Asia/Shanghai
./scripts/pa.sh configure
# 正常停止现有 PA 后重新运行 start，不要启动两个实例。
./scripts/pa.sh start
```

新安装模板默认开启；已有 `pa.json` 若没有 proactive 字段，则保持关闭，升级不会突然开始发消息。原有已部署实例有真实用户，故保留这一明确的开启步骤。全局关闭用 `init --proactive off`，重新生成配置并重启。

微信自然语言可以说“明天上午十点提醒我取快递”“快递已经拿回来了”。时间与任务理解依赖模型；可发“提醒列表”核对记录。控制命令由通道直接处理，不调用模型：

| 发给 PA 的内容 | 作用 |
|---|---|
| 提醒列表 / 提醒设置 / `/pa` | 查看偏好、任务编号、时间和状态 |
| 暂停提醒 / 恢复提醒 | 暂停或恢复自己的主动消息 |
| 少提醒一点 | 改为每天最多 1 条、间隔至少 6 小时 |
| 简短一点 | 改为最多 120 字 |
| 办完了 | 关闭最近一条已尝试发送的任务提醒，发送超时也能正确对应 |
| 晚点提醒 | 将最近一条任务延后 60 分钟，仍遵守预算与截止时间 |
| 不用提醒了 | 取消最近一条任务提醒 |
| `/pa done 编号` / `/pa drop 编号` | 明确完成或取消某一项 |
| `/pa later 60 编号` | 明确延后某一项 |
| `/pa quiet 22:00 09:00` | 设置静默时段 |
| `/pa add 2026-10-11T10:00+08:00 取快递` | 绕过模型解析，直接登记明确时间的提醒；换成自己的未来时间 |

多件事同时跟进时请带编号，避免“办完了”指代不清。`/new` 开始新对话但保留提醒台账，`/bot-cancel` 取消本轮观察和对话，不删除已经登记的未来待办。

本机可只读检查，不调用模型或发送消息：

```bash
./scripts/pa.sh proactive status
./scripts/pa.sh proactive preview
```

preview 是本地参考文案，不代表已经通过所有发送判断。它会列出静默、近期对话、冷却、额度或上下文过期等拦截原因；实际发送还要检查运行中的对话。输出不包含微信 context token。

## 接口与存储

- `plugins/proactive/observer.mjs`：观察者提示、输入投影、严格字段/时间/原话校验。
- `plugins/proactive/sniper.mjs`：跟进提示、内容预算和事实文案。
- `plugins/proactive/reach-out.mjs`：共享档位、分析/发送预算、主题去重、摘要和发送前原子领取。
- `plugins/proactive/policy.mjs`：纯时间与预算策略，不依赖微信。
- `plugins/proactive/engine.mjs`：台账状态机、反馈、调度和发送前复检。
- `plugins/proactive/index.mjs`：选择当前 Agent 核心的分析适配器。
- 微信通道仅提供经过白名单验证的消息、当前是否忙、一次文本发送函数和停止事件。新增 IM 可以复用 engine，换自己的身份与发送实现。

对话跟进台账在 `.runtime/proactive/<账号哈希>.json`；共享预算、候选、审批与发送证据在 `.runtime/hub/hub.sqlite`。文件，权限 0600，目录 0700；不进 Git 或源码包。账号、用户分别管理任务，模型只接收当前用户的消息和任务摘要；微信 token 不进入提示词、日志或本机检查输出。显式重新扫码后清掉旧上下文，等待新的来信；移出白名单的用户在下次启动时清除台账。

发送前先持久化 `sending` 并占用额度；接口成功只标记 `submitted`，不声称用户已读。超时/异常和崩溃遗留 `sending` 均记作 `delivery_unknown`，不会盲目重发。用户明确“晚点提醒”才开启新一次尝试。文件按原子替换写入并同步文件和目录，使用 Node 内置 SQLite 排他事务作为进程持有锁，崩溃自动释放，无需 Redis 服务；无状态变化的检查不反复写盘。

DSH 分析直接调用已有 LLM、不给工具且不创建对话 Agent。WorkBuddy 使用 `--tools ""`、禁用 hooks、不保存分析会话。Codex 使用独立空工作目录、ephemeral 会话、read-only、禁止审批升级，关闭 shell、web、MCP、Apps、插件和子 Agent，并拒绝分析中的工具事件。Codex read-only 不是整台电脑的读取隔离；仍需用户信任本机 CLI，不能当作零权限计算容器。

## 当前边界与下一步

1. 只观察用户主动发给 PA 的文字与本用户待办；没有持续读屏、读取所有 IM、日历接入或后台扫描手机。未来接入日历/物流等观察源应先定义事实来源和授权，再产出同样的候选。
2. “适合接收信息”目前依据用户设置、最近对话、任务时间和反馈推断；不知道用户是否在开车、开会或睡觉。后续可以在明确授权后加入日历忙碌、勿扰状态等信号。
3. 微信发送复用最近来信的 context token。项目采取最多 24 小时的本地保守有效期；这不是已核实的平台 SLA。过期保留待办等待新消息，已过任务窗口则过期。没有真实通道验收前，不保证跨天无互动推送。源码中 token 为可选字段也不能证明平台允许长期无上下文发送。
4. 电脑休眠、进程退出、模型不可用或平台拒绝时无法保证提醒到达。需要可靠跨天提醒的产品形态，应另接系统通知或允许独立推送的渠道；当前未实现。
5. 原话引用和高置信度阈值是约束，不是模型理解正确的证明。推送只用于准备与跟进，不自动打开手机、发给第三人或办理事务。

已做离线功能/并发/崩溃测试和隔离宿主启动；未向真实微信发送消息，未验证真实模型对自然语言任务的提取与文案质量。协议依据：[Codex 配置 schema](https://developers.openai.com/codex/config-schema.json)、本机 CLI help 与 DSH 锁定版本源码；进程锁依据 [Node 22.19 SQLite](https://nodejs.org/download/release/v22.19.0/docs/api/sqlite.html) 和 [SQLite 事务](https://www.sqlite.org/lang_transaction.html)。
