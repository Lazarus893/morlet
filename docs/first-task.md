# 首用的一件生活事

使用引导的主区域先接住自然交代，例如「帮我准备周日的生日」。Agent、消息入口和账号权限放在连接设置中，沿用实例选定的对话Agent，不改变全局分工。

## 用户流程

1. 写一句交代。草稿在服务端保存，不会自动发送。
2. 用户点击交给小满，建立独立Web会话。Chief读取真实时间与时区，只追问必要材料，一次至多三个问题，用户可以用一句自然话回答。
3. Chief通过结构化工具提出计划。页面展示日期、计划内容与准备步骤，暂不写账本。
4. 用户点击确认后，只授权保存这一份计划；修改计划要重新确认。Chief通过真实手账工具读取版本并保存，成功回执将确切事项与本轮流程关联。
5. 事实入账与设计生成分别展示。设计尚未完成或失败时，已有记录继续可用；只有当前账本revision的agent排版ready才称组件已整理。

进入页面、刷新或重新打开不会创建模型任务或重放确认。回到同一流程继续补充；已保存的旧事项与其他会话报告不会替代当前首用流程的完成证据。新的生活事显式开始，旧会话、流程与账本仍保留。

## 持久状态与恢复

`AgentHub`持久保存flow、独立会话、所有关联run、问题、计划版本、用户确认、草稿和可信保存回执。owner接口使用现有页面会话、同源与CSRF保护；Agent工具使用当前endpoint、lease和run校验。客户端不能指定账本关联、其他owner或消息来源。

草稿采用版本校验，冲突保留用户新输入并提示核对。开始、回答、确认等动作有请求幂等凭据，丢回执先读取状态，不盲目再次提交。模型运行期间可以离开，草稿保存和用户操作提交期间防止页面切换；页面关闭仍有未保存输入时提示保留。

执行暂停、登录错误、离线、等待批准、结果不明与取消分别展示。结果不明不会直接重试；先核对执行器，确认原任务停止后由用户决定继续。已保存的记录不能因后续模型失败改写成未保存。历史执行结果继续保留，不把失败报告改成成功。

## 授权边界

首用确认仅允许写入被确认的计划。未确认前手账只读，确认后的values与计划版本匹配；已有事项仅更新确切回执ID，不能新增重复记录。写入前再次校验当前运行与授权；保存后即使用户取消，实际入账事实仍需保留并关联。跨Hub/账本保存结果不明不重放。

首用流程不开放共同待办或定时提醒写工具，不安排通知、外发消息、订座、购买或操作手机。业务准备完成与计划记录完成有不同含义。其他普通对话的工具契约保持。

验收见[首用办理流程验收](verification-first-task.md)。账号授权转业务能力、签名Mac安装包与完整手机业务可靠性不属于本轮三个P0。
